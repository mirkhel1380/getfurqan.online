# Installed offline work: preserve the current experience

The owner requests all three existing reviewed reciters, with no separate download after installing the app, while preserving the current appearance, Quran scripts, published editions and functionality. Source substitutions have not been authorized. This is a requirement and compatibility checkpoint, not a completed offline release.

`mobile/compatibility-baseline.json` records SHA-256 hashes of the 180 files generated by native source `3322a4c2fdbc377a9e62f019b0962cbf7084aa5b` before installed-offline changes. It includes the HTML/CSS, reader and study adapters, edition selection, bundled source metadata, interface languages, brand assets, account/backup UI and existing audio interface. The record also identifies the existing public owner-signed APK and its build source; it does not claim every generated asset was independently extracted from that APK.

The normal mobile build and required checks compare generated files to this fixed checkpoint. The build never regenerates the baseline. Missing or changed existing files fail the build; new storage assets can be added. An intentional implementation change affecting a pinned file must be reviewed against this checkpoint rather than silently accepting a new baseline. Such a review must distinguish an internal storage change from a change in appearance, editions or scripture. No claim of complete visual or functional equivalence follows from hashes alone.

The installed-hadith transport adds one reviewed, synchronous local script to `hadith.html` and `hadith-book.html`. The verifier normalizes only that exact script at the start of the head in those two files; all original bytes still have to match the fixed checkpoint. No baseline hashes were regenerated. Fixtures reject altered text, reordered controls, duplicate hooks and additional scripts. All other existing generated files remain byte-identical.

All 64 currently selected hadith editions can now be included in both native install bundles without changing the reader or displayed source records. See [installed-hadith.md](installed-hadith.md). The network-disabled integration check exercises all 64 installed editions and the existing report/book adapter. Required checks for routes, reading hashes, 13 languages, account behavior, download integrity, transaction recovery, native audio and backup pass. Physical-device testing remains necessary. The public download URL and QR destination are unchanged; this work is not a fully offline release.

## Remaining dependency

The current app still fetches Quran content/fonts, translations, tafsir and prayer calendars from their sources. The existing recording library needs an explicit download and has a 200 MiB quota; that does not meet the requested installed-offline scope. Account creation, sign-in and cross-device sync also require a connection.

The Quran Foundation terms, updated 20 November 2026 and checked 25 November 2026, distinguish device offline synchronization/downloads from build-time bundled content. Content Sync is the required route for eligible offline data and its exception does not by itself authorize a prepackaged database/build-time bundle. Font/Mushaf-image bundling has separate conditions. The source issue must be resolved without replacing editions or falsely describing a first-launch download as content included in the installer.

Reference: https://api-docs.quran.com/legal/developer-terms/ (sections 2.2 and 3.1). This note records the applicable published integration conditions; it is not evidence of a separate permission grant.
