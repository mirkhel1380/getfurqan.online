# Offline recitation downloads · native 0.1.3 / build 4

The native app now has a Downloads page linked from its home cards and Listen page. It offers all 114 surahs and three reviewed recitations: Mishari Rashid al-Afasy (resource 7), Abdur-Rahman as-Sudais (3) and Mahmoud Khalil Al-Husary (6). The local chapter catalog is derived from the previously audited Quran API chapters response (SHA-256 `ff6ef5aadcc7710271179c0f9c1519c89ae613b11c8ba3265873c6c4fc6aed0b`). It contains chapter metadata, not generated Quran text. No audio recording is bundled; downloading starts only after the user's tap.

The download requests the existing Quran.com API recitation-by-chapter endpoint, checks the complete ordered chapter with the existing `AFQuranIntegrity.audioRows` guard, then checks each source URL against the reviewed reciter directory and its exact padded chapter/verse filename. Allowed HTTPS audio hosts are `verses.quran.com` and `mirrors.quranicaudio.com`; no user-provided URL or filesystem path is accepted. Redirects are disabled. Sources remain named in the app. Downloads do not synthesize speech, translations or tafsir and do not claim scholarly verification of recordings.

`@capacitor/file-transfer@2.0.6` downloads the unmodified MP3 on native platforms; `@capacitor/filesystem@8.1.5` stores it under `Directory.LibraryNoCloud/recitations-v1`. This is app-private storage, excluded from iOS cloud backup; Android backup was already disabled. External-storage access and permissions are not requested. The app privacy manifest includes the filesystem timestamp reason C617.1 and is part of Xcode resources. This is not a completed store privacy-label submission.

Each completed verse is checked for MP3 framing, byte length and SHA-256 with pinned `@noble/hashes@2.4.0`, then committed through an IndexedDB transaction. Its checksum detects later corruption of that downloaded file; it is not an independent published source checksum. Metadata and files use stable local keys; guest/account reading sync remains separate. A failed or stopped download preserves completed verses. Resume checks existing bytes and downloads only missing/changed/damaged recordings. Stop applies after the current verse finishes. If the page/app closes mid-request, a uniquely named uncommitted file may remain; it never appears as a completed verse, counts toward physical usage and is removed with that download. The library limit is 200 MiB and each completed recording is capped at 10 MiB; limits are checked before/after native transfer, so peak transfer usage may temporarily exceed the remaining allowance. No background-download completion is promised.

A transactional writer lease prevents concurrent pages modifying the library. It renews every five seconds, expires after 45 seconds if its page dies, and fences stale metadata writers. File names include a unique job token so an old native transfer cannot overwrite a resumed recording. Metadata writes and whole-pack deletion require the active lease. SHA-256 and writer exclusion do not depend on secure-context-only WebCrypto or Web Locks APIs; this matters for HTTP previews and custom-scheme WebViews. Tokens use cryptographic `getRandomValues`. Playback reads and verifies the saved bytes, then uses a local Capacitor file URL or a browser Blob URL. No network fallback occurs in the offline player; missing/damaged files ask for explicit repair. Whole-surah playback has verse selection and previous/next controls. Background audio and lock-screen controls remain separate work.

The new interface and explanatory copy are localized in all 13 app languages. Published Quran text, translation, tafsir and all 13 preserved reading adapters remain byte-identical. Quran reading/fonts/translation/tafsir still need internet; this change is offline recitation only. The standard website player and current public downloads are unchanged. Removing the app or clearing its data removes local downloads.

Validation completed:
- Core tests: 114/6,236 metadata; exact reciter/verse URL matching; offline local playback with network disabled in the fixture; interruption/resume; stop; corrupt/missing file repair; atomic metadata failure; invalid MP3 rejection; quota cleanup; concurrent writer rejection; scoped deletion and path/host rejection; complete 13-language placeholders.
- Actual IndexedDB transaction code against isolated `fake-indexeddb@6.2.7`: cross-page exclusion, stale-owner fencing, failure release, expired/crashed lease recovery and isolated metadata deletion.
- Mobile route/asset checks and native account checks remain in the required build checks. Native bundle verifiers compare the real packaged Downloads page/script and all 13 reading hashes; iOS also verifies the compiled privacy manifest.
- Browser QA: actual source Al-Fatihah/Alafasy downloaded (about 0.8 MiB), persisted after page reload, and played from a local Blob URL (readyState 4, no media error) while a QA-only wrapper rejected fetch requests. Next verse also played locally; pause worked. Dari RTL and dark appearance were inspected. The helper is only in the scratch preview and is not shipped.

Physical Android/iPhone downloads, airplane-mode playback, storage pressure, OS termination and native file URL handling still need device testing. iOS owner signing remains explicitly deferred; Android signing is still an ephemeral trial identity. Public Android 0.1.1 and the previously delivered iOS package/QR code are not replaced by an internal build.
